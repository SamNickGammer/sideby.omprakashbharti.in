# Contributing

Read the PRD and architecture before implementation. Create a focused branch from current main and use Conventional Commits: `feat:`, `fix:`, `docs:`, `chore:`, `refactor:`, or `test:`.

Submit a pull request explaining the problem, behavior change, checks performed, and limitations. Include screenshots for UI changes using synthetic data. Keep dependency lockfiles with the future application setup. Do not commit credentials or generated build output.

Run applicable checks before review. For this foundation, check Markdown links and SVG validity. Future application work must add lint, type checking, and meaningful behavioral tests. Squash merge reviewed changes and delete merged branches.
